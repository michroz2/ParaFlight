# Живая Архитектура Проекта (STATE)

## 1. Текущая Архитектура (As-Is)
Проект использует Clean Architecture (Feature-First) и Riverpod для управления состоянием.

**Поток данных (Data Pipeline):**
1. Данные считываются из файлов GPX.
2. Парсятся в сущности `LocationEntity` (в `gpx_parser.dart` с учетом размера окна `gpxSmoothingWindow`).
3. Поступают в `PlaybackNotifier` (Time Warp), который управляет временем симуляции.
4. Поток данных скармливается в `WindPipeline` через `windProvider`.
5. Поступают в кольцевой буфер (по умолчанию хранящий 120 сек истории) с использованием углового прореживания (`minCogChangeDeg`).
6. Обрабатываются через математическое ядро алгебраического фиттинга (Kasa Fit / `CircleKasaFit`).
7. Готовый вектор ветра и Airspeed выводятся на UI (FlutterMap) через Riverpod.

> 🎉 **Статус MVP достигнут!** Ядро приложения собирает данные, обрабатывает их и сохраняет настройки пользователя.

## 3. Технический долг (Tech Debt)
- Не реализовано меню редактирования самих переменных `WindConfig` (размеры окна, пороги).
- Необходимо пересмотреть архитектуру парсера (переход с `XmlDocument` DOM-парсера на SAX/событийный парсер) и работу с файлами для экстремальной производительности на огромных треках.

## 4. Правила и Конвенции (Conventions)
Проект строго подчиняется правилам, описанным в [RULES.md](RULES.md):
- Версионирование файлов ведется с инкрементом (`+0.1` для минорных, `+0.0.1` для патчей).
- Изменения в коде маркируются префиксами `// Новое:` / `// Изменение:`.
- Обязательны комментарии на русском языке.
- Обязательно комментирование закрывающих скобок (например, `// конец класса`, `// конец метода`, `// конец if`).
- Все commit messages обязательно пишутся на русском и начинаются с префикса текущей версии (например, `v0.3.0: ...`).
