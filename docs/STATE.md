# Живая Архитектура Проекта (STATE)

## 1. Текущая Архитектура (As-Is)
Проект использует Clean Architecture (Feature-First) и Riverpod для управления состоянием.

**Поток данных (Data Pipeline):**
1. Данные считываются аппаратно (Geolocator) или из файлов GPX (сверхбыстрый RegExp потоковый парсер в Isolate).
2. Поступают в PlaybackNotifier (Time Warp), который управляет временем симуляции.
3. Поток данных скармливается в WindPipeline через windProvider.
4. Поступают в кольцевой буфер (хранящий окно секунд истории) с использованием углового прореживания (minCogChangeDeg).
5. Обрабатываются через математическое ядро алгебраического фиттинга (Kasa Fit / CircleKasaFit).
6. Готовый вектор ветра и Airspeed выводятся на UI (FlutterMap) через Riverpod.

## 4. Правила и Конвенции (Conventions)
Проект строго подчиняется правилам, описанным в [RULES.md](RULES.md):
- Версионирование файлов ведется с инкрементом (+0.1 для минорных, +0.0.1 для патчей).
- Изменения в коде маркируются префиксами // Новое: / // Изменение:.
- Обязательны комментарии на русском языке.
- Обязательно комментирование закрывающих скобок (например, // конец класса, // конец метода, // конец if).
- Все commit messages обязательно пишутся на русском.
